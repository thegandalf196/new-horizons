LINUX SOURCE AND RELINKING

The engine source companion contains the exact Git revision recorded in
BUILD-IDENTITY.json and all pinned submodule contents. It excludes private build data,
purchaser assets and profiles. No original game assets are needed to compile.
A separate packaging/tooling source companion covers the package entry point and
notices. Consult BUILD-IDENTITY.json for the actual binaries and companion hashes.

For maintainers assembling a release from an exact checkout, first create the
matching engine source companion with tools/ci/git_source_snapshot.py. Then:
  python3 tools/ci/assemble_linux_candidate.py \
    --install /path/to/new/staging-directory \
    --engine-source /path/to/matching-engine-source.tar.gz \
    --source-commit FULL_40_CHARACTER_COMMIT \
    --source-repository . \
    --manifest assets/new-horizons/runtime-art-manifest.json \
    --output /path/to/new/raw-candidate

This checks the installed resource bytes, NHART mounts and required notices
against the source companion and creates BUILD-IDENTITY.json and SHA256SUMS.
It does not compile, extract artwork, prove every compiled source input, or
replace dependency/license audits and rendered acceptance. Current source
companions contain both NHART notice documents; only older companions lacking
them use the explicit source repository's exact-commit notice fallback.
Use tools/ci/stage_linux_client.py --help for final staging with independently
verified source, provider, header, ELF and build-provenance evidence. Neither
assembler is permission to publish an unverified candidate.

Build platform: Ubuntu 26.04 x86-64, ordinary GCC/G++ 15.2.0, C++20, CMake/Ninja.
Install suitable build tools and the development providers recorded in the header
inventory: Boost, SDL2/image/mixer/ttf, LuaJIT, oneTBB, minizip/zlib, squish, libcurl and the
FFmpeg codec/format/util/swscale/swresample development packages. Their exact
observed versions/source records accompany the package. No proprietary compiler
IR/plugin or LTO step was used in the recorded application build.

For a functional source rebuild, extract the engine source and use paths without
spaces for the following source/build aliases. Do not overwrite existing paths:
  /tmp/nh-linux-source
  /tmp/nh-linux-build

Configure:
  cmake -S /tmp/nh-linux-source -B /tmp/nh-linux-build --preset new-horizons-linux \
    -DCMAKE_INSTALL_PREFIX=/usr -DCMAKE_BUILD_RPATH_USE_ORIGIN=ON \
    '-DCMAKE_INSTALL_RPATH=$ORIGIN' -DCMAKE_BUILD_WITH_INSTALL_RPATH=ON \
    '-DCMAKE_C_FLAGS=-ffile-prefix-map=/tmp/nh-linux-source=. -ffile-prefix-map=/tmp/nh-linux-build=./build' \
    '-DCMAKE_CXX_FLAGS=-ffile-prefix-map=/tmp/nh-linux-source=. -ffile-prefix-map=/tmp/nh-linux-build=./build'
  cmake --build /tmp/nh-linux-build --target vcmiclient --parallel 2

vcmiclient is the CMake target name, not the shipped filename. This target produces
bin/new-horizons and its matching libvcmi.so; do not rename it to vcmiclient.

Stage to a NEW owned directory, not /usr:
  cmake --install /tmp/nh-linux-build --prefix /path/to/new/staging-directory

These are generic rebuild aliases. BUILD-PROVENANCE.json retains the actual
candidate's configure options, including its specific source/build prefix maps.

For the curated flat package retain only new-horizons, its matching libvcmi.so,
config, scripts, Mods/vcmi and Mods/new-horizons, plus the launcher, notices and
identity/source records. Do not copy the installed optional demo, builder tools,
purchaser assets or personal files. Recheck ELF imports, $ORIGIN, privacy and all
hashes after installation; build-tree success alone is insufficient.
Preserve Mods/new-horizons/NewHorizons.nhart and all installed New Horizons
notices. Ordinary builds use the committed package, not loose authoring inputs.

The exact glibc sources/patches are provided for the nonshared/startup boundary;
Boost/oneTBB and the other API-header source distributions are also included.
Use their retained build/patch material and ordinary compiler/CMake controls to
rebuild/relink with modified libraries. The launcher is not a signature lock or
sandbox and supports advanced explicit client/resource paths.

A source archive has no .git directory: its displayed Git stamp may differ from
an exact checkout unless equivalent revision metadata is supplied. Functional
rebuilding/relinking is supported; byte-identical output is not promised across
compiler, environment, timestamps or revision-metadata differences.
